## H-01 contract and implementation checklist

**Before:** `get_manager_receiving_workspace` returns a selected report with `id`, `sourceType` and `sourceReference`. `get_receiving_policy_evidence` classifies its stored FK lineage. Formal receipts appear in `get_inventory_request_register().receipts`; historical Phase 7B requests link by `get_replenishment_requests().receiving_report_id`. The UI previously called the historical RPC for both Production branches; if it failed, a formal report never reached `setWorkspace`.

**Correct behavior:** select one lookup by document family; match by selected report ID; preserve the existing `linkedRequest` context fallback and line prefill for historical receipts. Only `post_receiving_report` changes stock. The lookup correction must not create, revise, post, delete or settle any record.

**Regression:** (1) source/route and typecheck; (2) formal selected report with legacy lookup unavailable, and no call to legacy RPC; (3) legacy selected report with correct prefilled item and no formal RPC; (4) direct supplier selected report with neither request RPC; (5) failed selected lookup displays error; (6) a local browser Manager selection and DB read confirms the same report/document and no stock/ledger/quantity mutation; (7) repeated refresh and return from Requests behave the same. Distinguish executed tests from pending tests in [regression](FULLSTACK-HARMONIZATION-REGRESSION.md).

No database schema change is in scope for H-01. Any future migration requires an impact assessment, source/hash plan, deployment order, separate approval, rollback or restore path, valid/invalid/retry/role tests and a read-only hosted postcheck before it can be executed.
