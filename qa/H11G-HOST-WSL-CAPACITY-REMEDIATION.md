## Safe resolution path and exact decisions

1. **Host reserve first.** The owner can save work and close *chosen, currently unused* browser tabs/windows or editor instances. Browser and editor working sets were about 2,556 and 1,639 MiB; these figures identify where to look, not promised recovery. Do not terminate any app automatically. Re-measure Windows free RAM and WSL available/swap under the same workload. A practical gate for another trial is at least 2 GiB Windows free and stable WSL above 800 MiB, with no dip below the script's hard 400 MiB floor. The 2 GiB host target is a proposed trial reserve, not a validated hardware requirement.
2. **Fixture ownership decision.** The owner must identify a precise idle RRJ disposable fixture and verify that no browser, test, job, Studio/log use or downstream workflow depends on it during a stated window. For the existing executable path, this is only `supabase_analytics_rrj_h08c_history_20261015`; H-08C Studio/log/vector effects need review. The H-07, H-08B, Manager lifecycle, phase-3, and demo variants are review candidates but have no implemented whole-stack stop and no verified idle evidence. Phase-8 and replay need specialist review. No unrelated todo, `isolated-stack`, H-09, canonical demo, recovery or unlabeled item belongs in an automated pause.
3. **If a future trial becomes eligible:** refresh exact IDs, labels, ports, mounts, running states, protected health, Windows and WSL resource samples; write the script's restore journal before stopping; use only its exact H-08C opt-in target; compare Windows/WSL RAM, swap, pressure, Auth/REST/SQL and restart counts during the pause; restore that same original running state immediately; verify identity and health; then observe for several minutes. Abort on any new below-400 MiB reading or failing retained health check. No such trial occurred in H-11G.
4. **WSL configuration remains a proposal.** An increase from the current 7.62 GiB VM ceiling to 9 GiB would expose at most ~1.38 GiB more VM allowance, not create RAM. At 536–737 MiB host free, it has no defensible host reserve. A smaller VM ceiling could return host capacity but would worsen current WSL pressure unless RRJ fixture concurrency is reduced first. Any `.wslconfig` memory or swap value requires a separately approved Docker/WSL outage, saved current settings, disk/reserve policy and post-change verification. No config change was made.
