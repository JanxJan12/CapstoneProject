### Rollback assessment (plan only)

Before any separately authorized deployment, capture the *then-current* hosted `pg_get_functiondef`, owner, ACL, configuration, grants, OID, and digest in a restricted release record. Review an exact five-argument `CREATE OR REPLACE FUNCTION` reversal from that baseline and its required ACL restoration; rehearse it in a disposable representative database, including a draft created under 02B. `CREATE OR REPLACE` can restore the prior body without altering historical receipt rows, but restoring the old body would reject the current null-inspector frontend. Rollback therefore requires a temporary linked-Receiving pause and an older compatible frontend or a separately reviewed compatibility measure before reopening. Do not rewrite UUID inspector values in new drafts, delete drafts, or default to destructive database restore. The release owner must authorize rollback based on captured evidence and operational impact. If other writes occurred, assess them independently before any point-in-time restore.
