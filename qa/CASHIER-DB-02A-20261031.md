## 3. Independent dependency verification

A source-wide reference search across `src`, scripts, tests, routes, build configuration and styles found each component name only in its own definition. The candidate files are not exported by a barrel. `src/app/routes.tsx` lazy-loads the Cashier module, not these files; `src/modules/cashier/index.tsx` mounts `ShiftSettlementPage`. The page imports `ShiftOverview`, `StartShiftDialog`, `EndShiftDialog` and `ClosedShiftHistory`, with no import, dynamic import, conditional render or feature flag for either candidate. Manager `src/modules/manager/index.tsx` lazy-loads `ClosedShiftHistory`, not either candidate. No Storybook, preview, generated registry, active test fixture or build entry references the candidate names. Historical QA documents refer to them as past implementations; those records were preserved.

`ShiftAuditTable.tsx` alone imported `ShiftOutcomeBadge.tsx`; no other source or test imported the badge. That helper became exclusively orphaned and was removed. The badge used `getVarianceOutcome`, but `ShiftMetrics.tsx` still uses that shared utility, so `shiftSettlementUtils.ts` remains. Shared `CashierButton`, `SectionHeading`, `StatusBadge`, `Toast`, formatters, types and CSS are used by active components and remain. No style selector was specific to the removed components.

The hook `useShiftSettlement.ts` had report selection (`reportShiftId`), a setter, report totals, and unused `latest/totals` projections. The only hook consumer is `ShiftSettlementPage`, which reads none of those fields and instead uses `activeShift` and `shiftTotals`. The report-only state, derivation and now-orphaned `calculateShiftTotals` import were removed. The hook's live start/end handlers, pending-payment list, loading/error state, server-returned closure toast and dialog controls were left intact.
