The ordinary export alone was insufficient for the prior local restore: cross-schema Auth/Storage policies, trigger and effective grants required the protected supplement. The existing one-drive backup and synthetic drill therefore do not establish a complete, independently recoverable hosted system. The recovery source and target stacks, the original backup, and the demonstration stacks were preserved. No recovery script was rerun against them because those scripts write local fixture/target state and would not prove recovery from a complete approved off-device set.

## Required protected rehearsal

**REQUIRES APPROVAL** before any new hosted export or private byte access: the [hosted recovery approval record](HOSTED-RECOVERY-APPROVAL-20261014.md) must name the exact project, accountable owner, restricted destination, independent off-device location, encryption/key custodian, private-object-byte route, restore environment and coverage. Capture roles/schema/business data, managed Auth/Storage metadata, every current private object byte, RLS/policies/grants/functions/triggers/extensions, migration ledger and required provider/configuration settings. Keep credentials, paths and payloads private.

After approval, verify per-file and archive hashes **from the independent copy**, test extraction and owner-held key recovery, then restore into a new named unlinked target. Compare catalog fingerprints, all table counts and key relationships, Auth/profile joins, private bucket metadata and byte hashes, RLS/grants/role denials, migration history, order/payment/delivery and Receiving/stock reconciliation. Record recovery time, failed steps, and rollback/abort instructions. A successful synthetic drill remains useful procedure evidence, but production DR stays **NO-GO** until this complete rehearsal passes.
