# Presenter script — RRJ’s Food-House defense demonstration

**Target:** 10–15 minutes, on the isolated synthetic local stack. Use a laptop with Chrome and two browser profiles. The kitchen screen is best shown in a second tab or external display; use Rider web if the Android emulator is unavailable. Keep the private role card off the projector. Each narration sentence below distinguishes a software event from a real-world event. The full Customer Chrome → Cashier Chrome → KDS Chrome → Rider emulator → Customer Chrome sequence passed on the same fresh `ORD-000017`; use a new order for the panel demonstration.

## Before the panel enters

Start the chosen slot and web server per `DEFENSE-DEMO-ENVIRONMENT-20261014.md`. Check the yellow banner on `/auth`, `/customer`, `/manager`, `/production`, `/cashier`, `/kitchen`, and `/rider`. Keep the private role card out of screen sharing. Sign Customer and Cashier into separate Chrome profiles and activate the KDS using the private terminal secret. Prepare a new local Cashier shift. Use a new synthetic reference and proof image. Open `DEFENSE-DEMO-RESET-AND-FALLBACK-20261014.md` on the presenter laptop.

## Presenter boundaries

The test order numbers in the QA JSON files are already consumed or advanced; `ORD-000017` is delivered and must not be used as a fresh Customer checkout. New live runs require fresh order/request identifiers. A real GCash payment, actual recipe/opening balance, independent Messenger dispatch, a physical delivery, OS print, Google OAuth, and production deployment are not part of this local demonstration. Show the Android app only after its installed APK and emulator/backend connection are verified for this session; otherwise show Rider web and mark Android UI actions untested.
