## 1. Implementation and pre-edit baseline

DB-01's [register](CASHIER-DB-01-ELIMINATION-REGISTER-20261031.csv) and [inventory](CASHIER-DB-01-OBJECT-INVENTORY-20261031.csv), [DB-02A](CASHIER-DB-02A-20261031.md), [DB-02B decision](CASHIER-DB-02B-20261031.md), its [synthetic replay](CASHIER-DB-02B-DISPOSABLE-REPLAY.sql), and prior [manual findings](CASHIER-MANUAL-FINDINGS-20261030.md) were reviewed before editing. The canonical migration directory had 70 files through `20261030034730_cashier_owned_transaction_history_read.sql`. The Supabase CLI v2.33.9 `migration new` command created **`supabase/migrations/20261031155629_cashier_db_03a_remove_redundant_profile_rider_objects.sql`**, making it migration 71. No old migration was edited.

Read-only hosted catalog was rechecked: `profiles_set_updated_at`/`trg_profiles_set_updated_at` on `public.profiles` and `riders_set_updated_at`/`trg_riders_set_updated_at` on `public.riders` are enabled BEFORE UPDATE FOR EACH ROW, `tgtype=19`, no WHEN or column restriction, all executing `public.set_updated_at()`. The function sets only `NEW.updated_at=now()` and returns NEW; 11 other tables also use it. `profiles_select_own` and `profiles_view_own` are authenticated permissive SELECT policies with respectively `(SELECT auth.uid())=id` and `id=(SELECT auth.uid())`; `managers_view_profiles` and `profiles_update_own` remain required. Authenticated SELECT and `contact_number` UPDATE grants, anon denial, RLS enabled, and `get_current_shift_walk_in_sales()` were inspected in DB-02B and preserved here.

The historical local `20261013071937_remove_duplicate_timestamp_triggers.sql` already drops the two `trg_` triggers, while the hosted ledger does not show that version and hosted still has both. DB-03A therefore accepts **only** two precise trigger pre-states: both reviewed extras present, or both already absent after the earlier local cleanup. It rejects one-sided cleanup or a changed trigger definition. The two `DROP TRIGGER IF EXISTS` statements are guarded compatibility with that known history, not open-ended idempotence. The profile policy must be present with its reviewed expression and is dropped without `IF EXISTS`. Guards also require the retained triggers, own/Manager/UPDATE policies, RLS, timestamp function and legacy RPC. A transaction brackets the three DDL statements. No `CASCADE`, table/column change, function drop, or grant change is in the migration.

## 3. Current-schema migration application — **PASS, separate fallback**

For a distinct current-schema test, a schema-only PostgreSQL custom dump was read from the existing `supabase_db_rrj_current_contract_integration_2026102` database and restored into a **new** disposable Supabase PostgreSQL 17.11 container, `rrj_cashier_db03a_schema_clone_20261031`. The existing container was queried/dumped read-only; its rows and services were not changed. The restore selected `auth` and `public` objects, with `--no-owner --no-acl` because unrelated Realtime `log_min_messages` and default-privilege entries cannot be replayed by the disposable postgres role. This is **not** a full hosted-schema restore and does not recreate every ACL, Storage, Realtime object or migration ledger. For role tests, the relevant hosted profile grants were applied transiently inside rollback-only transactions. The source and clone both had **36 public tables, 414 public table columns, 134 public indexes and 276 public constraints**. The exact target trigger/policy definitions and `auth.uid()`/`current_user_role()` definitions matched the hosted inspection.

On a clone with both extra triggers present, preflight was `36 tables / 2 target triggers / 1 target policy / legacy RPC present`. Applying the DB-03A file with `psql -v ON_ERROR_STOP=1` returned `BEGIN, DO, DROP TRIGGER, DROP TRIGGER, DROP POLICY, COMMIT` and exit 0. On a second clone, the earlier local trigger-cleanup migration applied first; DB-03A then returned two expected missing-trigger notices, dropped only the policy, committed, and exited 0. This proves compatibility with both documented pre-states, not that the full 71-file history is clean.

Two negative rehearsals proved fail-closed behavior. Dropping only `trg_profiles_set_updated_at` first made DB-03A raise **`DB-03A: partial prior timestamp cleanup`**, leaving `profiles_view_own` intact. Changing only `profiles_view_own` to `USING (true)` made DB-03A raise **`DB-03A: own-profile SELECT policy drift`**, leaving both target triggers intact. Neither was forced through.

## 5. Restoration and recovery — **PASS for object recreation**

Object recreation is **not** proof of full disaster recovery or protection of state changed after deployment. Backup, migration-ledger reconciliation and a verified operational rollback remain separate hosted prerequisites.
