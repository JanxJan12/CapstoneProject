# Customer UI/UX recommendations — 22 October 2026

## Evidence boundary and experience overview

This is a source-level design assessment of the active `src/modules/customer/index.tsx`. A local Vite server was started, but the computer-use runtime exposed no browser/app surface and could not create an in-app browser tab. **No Customer screen was rendered or screenshot captured in this audit.** All seven target widths (320, 360, 390, 430, 768, 1024, 1440 px), contrast, keyboard, focus, safe-area, and zoom behavior require later visual acceptance. Code shows a coherent warm restaurant palette, strong menu CTA, customer-facing status and retry states, 44 px or larger controls in many key paths, and a checkout confirmation card. This report does not repeat earlier concerns already addressed in current source.

## Visual system and navigation

Use the existing amber/brown/cream identity and shared card/button primitives. The source mixes 9 px captions, 10–12 px controls, and 14–16 px body copy (`HomePage`, `CustNav`, checkout); establish a readable mobile type floor and test contrast rather than asserting a contrast failure from CSS. `CustNav` includes a mobile dialog with `aria-modal` and key handling; verify focus placement, trap, return focus, escape, and menu close in a real browser. `CustomerApp` uses one URL for all views. A URL for menu/history/tracking would make refresh/back behavior understandable while preserving server ownership and the checkout retry token. This is CUST-04, not a request for new backend data.

## Required states and accessibility acceptance

Current source includes loading/empty/error states for menu, cart, tracking, history, and profile, as well as checkout progress and success. Raw Supabase messages remain visible on several error paths (CUST-01). Replace them with concise action text and a retry button while retaining diagnostic details in logs. Check status/alert announcements for duplicate speech, input error focus, file upload keyboard access, and confirmation focus in an authenticated browser. Honor `prefers-reduced-motion` for the hero motion and transition paths as well as `CustNav`; source inspection alone does not establish whether the animation library suppresses those automatically. Target WCAG 2.2 AA through manual and automated rendered checks.
